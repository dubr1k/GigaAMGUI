# GigaAM v3 — зависимости офлайн-сборки под macOS x86_64 (Intel).
#
# Почему отдельный файл, а не requirements.txt: под macOS x86_64 колёса PyTorch
# закончились на 2.2.2, а проект требует torch>=2.6.0 — общий набор там просто
# не разрешается (issue #45). Понижать пин ради Intel нельзя: pyannote.audio
# 3.1.1 завязан на API torchaudio, а Blackwell требует ветку 2.8.
#
# Поэтому Intel-сборка идёт без torch и без mlx. Вместе с torch отпадают
# pyannote.audio, lightning, speechbrain, accelerate и сам пакет gigaam:
# распознавание, VAD и диаризация целиком идут через onnx-asr + ONNX Runtime,
# для которых на x86_64 доступны провайдеры CoreML и CPU.
#
# Ограничение колёс onnxruntime 1.23.2 под macOS x86_64 — macOS 13 и новее.
#
# Транзитивные зависимости намеренно не приколочены: без torch дерево
# разрешается иначе, чем на других платформах, и полный lock здесь только
# ломал бы установку. Прямые пины совпадают с requirements.txt.

# ── ASR / диаризация: только ONNX ────────────────────────────────────────────
numpy==2.2.6
onnx-asr==0.12.0
onnxruntime==1.23.2

# ── Аудио ────────────────────────────────────────────────────────────────────
librosa==0.11.0
soundfile==0.13.1
soxr==1.0.0
scipy==1.16.3

# numba и llvmlite — транзитивные зависимости librosa, но приколочены здесь
# намеренно. С numba 0.67 и llvmlite 0.49 колёса под macOS x86_64 больше не
# выпускаются (только Apple Silicon), остаются одни sdist. Без пинов pip берёт
# свежую версию и уходит собирать llvmlite из исходников, требуя полный
# LLVM-тулчейн, — сборка падает на CMake `Could not find LLVM`. 0.62.1/0.45.1 —
# последние версии с колёсами под x86_64, они же стоят в requirements.txt.
numba==0.62.1
llvmlite==0.45.1

# ── Модели: локальный кэш и загрузка ─────────────────────────────────────────
huggingface-hub==0.36.0
requests==2.32.5
certifi==2025.11.12

# ── GUI и экспорт ────────────────────────────────────────────────────────────
PyQt6>=6.10.0
python-docx>=1.1.2
python-dotenv==1.0.0
yt-dlp==2026.3.17
typing_extensions==4.15.0
