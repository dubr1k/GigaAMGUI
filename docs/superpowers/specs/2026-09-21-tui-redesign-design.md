# TUI 2.0: русский язык, вкладки, мышь, панель параметров — дизайн

Дата: 2026-09-21. Статус: одобрен пользователем («приступай»), подход B.

## Цель

Сделать Rust TUI (`tui/`) понятным без чтения справки: русский интерфейс по
умолчанию с переключением на английский, структура вкладок как в PyQt/Liquid,
все текущие параметры видны на экране и меняются кликом или клавишей,
подсказка «что делать дальше», справка по `?`, поддержка мыши. Попутно —
обновить ratatui/crossterm до актуальных версий и разбить `main.rs`
(3 300 строк) на модули.

Не входит: Live-режим, ссылки на медиа, новые виджет-библиотеки, изменения
Python-воркера и его протокола, headless-режим (остаётся как есть, только
переезжает в модуль; его `--help`/сообщения — на английском, это контракт для
агентов и скриптов).

## 1. Зависимости

`ratatui 0.30.2`, `crossterm 0.29`, `ratatui-image 11.1` (совместимы между
собой; `ratatui-image 12` — rc, не берём), `image 0.25` без изменений.
Известные изменения API 0.29 → 0.30: `Frame::size()` → `Frame::area()` (уже
используется), `ratatui::prelude` сохранён, `Terminal::draw` без изменений,
`Rect::inner(Margin)` — сигнатура прежняя. `ratatui-image 11`: `Picker::from_query_stdio()` и `StatefulImage` сохранены; проверить `new_resize_protocol` при обновлении (в 8.x → `Picker::new_resize_protocol`, в 11 может быть `picker.new_resize_protocol(image)` — компилятор подскажет). Обновление — отдельный первый коммит, без функциональных изменений; все 39 тестов и pty-прогон должны пройти до редизайна.

## 2. Язык (i18n)

- `enum Lang { Ru, En }`, хранится в `App.lang` и в `TuiSettings.language`
  (`"ru"`/`"en"`). Синхронизация с десктопом: ключ `language` в
  `user_settings.json` (там `"ru"`/`"en"`), по правилам Task 9 (десктоп
  установлен → читаем/пишем туда).
- Приоритет при старте: `--lang ru|en` (аргумент) → настройка → `"ru"`.
- Переключение: `/lang ru|en`, пункт «Язык» на вкладке «Настройки», клик по
  индикатору `RU`/`EN` в шапке. Меняется мгновенно (перерисовка).
- Механизм: `i18n.rs` с `pub fn t(lang: Lang, key: &str) -> &'static str` над
  статической таблицей `&[(&str, &str, &str)]` (ключ, ru, en). Ключи —
  осмысленные идентификаторы (`"tab.processing"`, `"hint.add_files"`), не
  русские фразы (в Liquid ключ = русская фраза; в Rust это неудобно для
  `format!`). Строки с параметрами — `tf(lang, key, &[("n", "3")])` с
  подстановкой `{n}`.
- Тест: каждая запись имеет непустые ru и en; каждый ключ, встречающийся в
  коде как `t(.., "…")`, есть в таблице (тест читает исходники `ui/*.rs`,
  `commands.rs`, `app.rs` регуляркой `t\(\s*[a-z_.]+\s*,\s*"([^"]+)"`).
- Сообщения воркера (`log`, `progress.message`) приходят по-русски — так они
  формируются у источника (проект перевёл журнал в 2.2.1). В английском
  режиме TUI показывает их как есть (как делает Liquid). Стадии `progress.stage`
  переводятся таблицей `stage.*` (те же 7, что в PyQt `_STAGE_NAMES`).
- Команды остаются английскими идентификаторами (`/backend`, `/formats` —
  это API для рук), их описания переводятся.

## 3. Раскладка

```
┌ GigaAM  ● готов   RU │ ? справка ─────────────────────────────┐  шапка (1)
│ [1 Обработка] [2 LLM] [3 Настройки] [4 Журнал]                 │  вкладки (1)
│ ┌ Очередь (2 файла) ───────────┐ ┌ Параметры ───────────────┐ │
│ │ › 1. запись.wav      ожидает │ │ Движок      auto         │ │
│ │   2. встреча.m4a     готово  │ │ Модель      v3_e2e_rnnt  │ │  основная
│ │                              │ │ Форматы     txt, srt     │ │  область
│ │                              │ │ Диаризация  выкл         │ │
│ │                              │ │ Спикеры     авто         │ │
│ │                              │ │ Звук        auto         │ │
│ │                              │ │ Папка       рядом с файлом│ │
│ └──────────────────────────────┘ └──────────────────────────┘ │
│ ┌ Прогресс ────────────────────────────────────────────────┐ │
│ │ ████████░░░░░░░░ 42%  Распознавание речи…  00:03:10/00:07:30│ │
│ │ Сохранено: запись.txt, запись.srt                          │ │
│ └──────────────────────────────────────────────────────────┘ │
│ ▶ Далее: нажмите s или [Запустить], чтобы начать обработку     │  подсказка (1)
│ › /                                                            │  ввод (1+)
│ s запустить · L LLM · d диаризация · ? справка · q выход        │  футер (1)
└────────────────────────────────────────────────────────────────┘
```

Вкладки: `Tab`/`Shift+Tab` или клик по заголовку; `F1..F4` — прямой переход
(цифры 1–9 заняты выбором в меню). Активная вкладка не сохраняется.

**Обработка.** Слева очередь: номер, имя (усечение посередине), состояние
(`ожидает / в обработке / готово / ошибка`, из `file_index`/`file_completed`),
выделение `↑↓`/клик, `Delete`/`Backspace` — убрать, `Ctrl+↑↓` — переставить.
Пустая очередь — текст «Вставьте путь к файлу или папке и нажмите Enter».
Справа «Параметры»: 7 строк — клик или `Enter` на строке (когда фокус в
панели, переключение фокуса `→`/`←`) открывает то же меню, что соответствующая
`/команда` (`/backend`, `/model`, `/formats`, `/diarize`, `/speakers`,
`/audio-mode`, `/output`). Внизу «Прогресс»: gauge + стадия + таймкод, список
сохранённых файлов. Кнопки в шапке блока: `[Запустить]` / `[Остановить]`
(клик = `s` / `Esc`).

**LLM.** Слева «Транскрипты» (результаты сессии + `/llm-file`, нумерованные,
`Delete` убирает), справа «Что сделать»: чекбоксы `[x] Выжимка [ ] Задачи
[ ] Термины [ ] Свой промпт` (клик/`Space` переключает), поле промпта,
строка «Провайдер: Claude Code · 2.1.278» (клик → меню провайдера), кнопки
`[Запустить LLM]` `[Отменить]`. Низ — «Ответ»: стрим/результат с прокруткой
(колёсико, `PgUp/PgDn`), заголовок с режимом и «сохранено в …».

**Настройки.** Один список (List с состоянием): Язык, Мышь, Пет, Движок,
ONNX-провайдер, Модель, Движок диаризации, Звук, Субтитры (разбиение,
строк, ширина), LLM: провайдер, модель, API URL, ключ (скрыт `••••`),
температура, путь к CLI, внутренний provider, доп. аргументы, инструменты
агента. `Enter`/клик → меню выбора (для перечислимых) или строка ввода
(текст/число — командная строка внизу предзаполняется `/llm-model `, как
сейчас делает `/settings`). Значения читаются из `App` при каждой отрисовке.

**Журнал.** Весь лог (не 5 строк) с прокруткой, `End` — к последним, автопрокрутка
при новых строках, если пользователь внизу. `Ctrl+L` очищает.

**Справка (`?` или `F1`-нет, `F1` занят вкладкой → `?` и `/help`).** Оверлей
поверх текущей вкладки: клавиши, команды с описаниями, закрывается `Esc`/`?`/
кликом. Локализована.

**Меню выбора** (существующие `command_menu_options`) остаются внизу над
строкой ввода, пункты кликабельны, `0`/`Esc` — назад.

## 4. Мышь

- `crossterm::event::EnableMouseCapture` при старте, `Disable` при выходе
  и перед запуском внешнего процесса (нет таких). Настройка «Мышь: вкл/выкл»
  (`TuiSettings.mouse`, по умолчанию `true`; `/mouse on|off`). При выключении
  — `DisableMouseCapture` на лету. В справке — примечание: для выделения текста
  зажмите Shift (Linux/Windows) или Option (macOS Terminal/iTerm), либо
  выключите мышь.
- Hit-test: при отрисовке каждая интерактивная область регистрируется в
  `HitMap` (`Vec<(Rect, Action)>`, очищается каждый кадр). `Action` — enum:
  `Tab(Page)`, `SelectFile(usize)`, `OpenMenu(&'static str)` (имя команды),
  `ToggleMode(&'static str)`, `Button(ButtonId)`, `ToggleLang`, `Help`,
  `MenuItem(usize)`, `ScrollArea(AreaId)`.
- События: `MouseEventKind::Down(Left)` → первый `Rect` в `HitMap`, содержащий
  точку → `dispatch(action)`, та же функция, что и для клавиш (без дублирования
  логики). `ScrollUp/Down` → область под курсором из `ScrollArea` → сдвиг
  `scroll` соответствующего списка. Двойной клик не используется.
- Тесты: `HitMap::hit(x, y)` возвращает верхний `Action`; `dispatch` для
  каждого `Action` меняет состояние так же, как клавиша (таблица соответствий
  в тесте).

## 5. Подсказка «Далее»

Функция `next_step(app) -> &'static str` (ключ i18n), приоритет сверху вниз:
1. воркер недоступен → «Воркер не запущен: выполните gigaam --update»;
2. идёт обработка → «Esc — остановить после текущего файла (Esc×2 — сразу)»;
3. идёт LLM → «Esc — отменить LLM»;
4. очередь пуста и нет результатов → «Вставьте путь к файлу/папке и Enter»;
5. очередь не пуста, не запущено → «s или [Запустить] — начать»;
6. есть результаты, LLM не запускался → «L — выжимка/задачи через LLM»;
7. есть результат LLM → «r — показать/скрыть ответ; вкладка Журнал — детали».
Тест: таблица состояний → ключ.

## 6. Структура кода

`tui/src/`:
- `main.rs` — точка входа: аргументы, headless-ветка, терминал, цикл событий
  (≤ 300 строк).
- `app.rs` — `App`, `Page`, `handle_message`, `next_step`, `dispatch(Action)`.
- `i18n.rs` — `Lang`, таблица, `t`/`tf`.
- `settings.rs` — `TuiSettings`, пути, синхронизация с десктопом, `.env`.
- `commands.rs` — `COMMANDS`, `run_command`, `command_menu_options`,
  `apply_command_menu`, подсказки.
- `worker.rs` — `spawn_worker[_with]`, `send`, `LlmTool`, реестр.
- `headless.rs` — `parse_headless_args`, `run_headless`, `HEADLESS_USAGE`.
- `ui/mod.rs` — `draw`, `HitMap`, `Action`; `ui/processing.rs`, `ui/llm.rs`,
  `ui/settings.rs`, `ui/log.rs`, `ui/help.rs`, `ui/menu.rs`.
- `pets.rs` — единорог.
Тесты — в модулях (`#[cfg(test)] mod tests`), существующие 39 переезжают без
изменения смысла; `isolated_config_dir` — в `settings.rs` под `#[cfg(test)]`
и `pub(crate)`.

Разбиение — механическое, отдельным коммитом ДО редизайна (после обновления
зависимостей): поведение и тесты неизменны.

## 7. Совместимость

- `tui_settings.json`: новые поля `language`, `mouse` с `#[serde(default)]`.
- Все `/команды`, хоткеи и headless-режим работают как раньше; `/settings`
  теперь переключает на вкладку «Настройки» вместо меню.
- `gigaam --update` и skill не затрагиваются.
