# TUI Colour Themes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the TUI user pick a colour scheme — the 99 oh-my-pi palettes (MIT), our own `dark-hermes-pink` (hot-pink-on-black look requested by the user: accent `#f0559a`, light pink `#f9a8d4`, deep `#c9257a`, mint `#4ade80` for «ready»/success), plus `default` (today's colours) and `mono` — via `/theme <name>`, a «Тема» row on the Settings page, and `--theme` for one run; persisted in `tui_settings.json`.

**Architecture:** `tui/themes/*.json` are bundled at compile time; `tui/src/theme.rs` parses them into a `Palette` of 12 named colours and exposes `Theme::by_name`, `Theme::names()`, `App::palette()`. Every hard-coded `Color::…` in `tui/src/ui/*.rs` becomes a palette field. `default` reproduces the current look exactly so nothing changes for existing users.

**Tech Stack:** Rust, ratatui 0.30, serde_json (already a dependency), `include_str!` via a generated `themes/mod.rs`… no — simpler: a `build.rs`-free approach using the `include_dir` crate is an extra dependency; use a small `tui/src/theme/catalog.rs` generated by `scripts/tui/gen_theme_catalog.py` that emits `pub static THEMES: &[(&str, &str)] = &[("dark-monokai", include_str!("../../themes/dark-monokai.json")), …]` — committed, regenerated when JSONs change (a test asserts catalog == directory listing).

**Spec:** design approved in chat 2026-09-21 (no separate spec): 99 oh-my-pi palettes + `dark-hermes-pink` + `default` + `mono`; `/theme` with completion and a scrollable menu; Settings row; `--theme`; persisted `theme` key; no desktop sync; README/README_EN/CHANGELOG.

- Test: unit tests inside `theme.rs`

**Interfaces:**
- Produces:
  ```rust
  pub(crate) struct Palette { pub accent: Color, pub border: Color, pub border_accent: Color, pub border_muted: Color,
      pub text: Color, pub muted: Color, pub dim: Color, pub success: Color, pub warning: Color, pub error: Color,
      pub selected_bg: Color, pub status_bg: Color }
  pub(crate) struct Theme { pub name: &'static str, pub palette: Palette }
  impl Theme {
      pub(crate) fn by_name(name: &str) -> Option<Theme>;   // "default", "mono", or any catalogue name
      pub(crate) fn names() -> Vec<&'static str>;            // "default", "mono", then catalogue sorted
      pub(crate) fn default_theme() -> Theme;
  }
  ```
- JSON mapping: `colors.<key>` value is either a `vars` name, a `#rrggbb` hex, or `""` (= terminal default → `Color::Reset`). Palette keys: `accent, border, borderAccent, borderMuted, text, muted, dim, success, warning, error, selectedBg, statusLineBg`; missing key → fall back to `text`/`Reset`. `default` palette = today's constants: accent `Rgb(92,155,255)`, secondary/muted `Rgb(180,195,220)`, selected_bg `Rgb(40,60,100)`, help bg `Rgb(20,24,34)`, gauge bg `Rgb(40,40,50)`, `White`, `DarkGray`, `Gray`, `Green`, `Red`, `Yellow` per their current uses (read `ui/*.rs` and record each use before replacing). `mono`: everything `Reset` except `accent = Reset` + bold handled in Task 2 via `Modifier`.
- Generator: `scripts/tui/gen_theme_catalog.py` writes `tui/src/theme_catalog.rs` with `pub(crate) static THEMES: &[(&str, &str)]` sorted by name; a Rust test asserts `THEMES.len() == 100` (99 oh-my-pi + `dark-hermes-pink.json`, same JSON format, already in `tui/themes/`) and a Python test (`tests/test_tui_theme_catalog.py`) asserts the generated file matches the generator's output for the current directory (so a stale catalogue fails CI).
