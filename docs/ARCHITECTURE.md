# Архитектура и стратегия рефакторинга

Документ описывает, как устроен проект после прохода по поддерживаемости
(ветка `refactor/maintainability-pass`, октябрь 2026), какими правилами он
делался и что осталось на следующие итерации. Правила для повседневной работы —
в [AGENTS.md](../AGENTS.md); здесь — картина целиком и причины решений.

## 1. Карта системы

```
 PyQt6 (app.py, src/gui)   Web (web/)   REST (api.py)   MCP (src/mcp_server.py)   CLI (cli.py)
          │                    │             │                 │                     │
          │                    └─────────────┴────────┬────────┴─────────────────────┘
          │                                           │
          │         TUI (tui/, Rust) ─┐               │
          │      Liquid (macos/, Swift)┴─ JSONL ─ src/tui_worker.py (+ live/llm/input services)
          │                                           │
          ▼                                           ▼
   src/services ── transcription_service / transcription_api / llm_service + cli_tools / …
          │
   src/core ────── processor (стадии) · asr (pytorch/mlx/onnx, longform, chunking)
          │        diarization (pyannote/onnx/sortformer) · export · progress · runtime_options
   src/live ────── session (фасад) · asr-планировщик · timeline/mixing · recorder · capture/*
          │
   src/utils ───── ffmpeg, предобработка, swappable torch runtime, model cache, llm_client, …
```

Правила слоёв: фронтенды зависят от `services`/`core`; `core` не импортирует
`services` и фронтенды; headless-фронтенды никогда не импортируют `src.gui`.
Протокол worker'а (TUI и Liquid) меняется только аддитивно: клиенты
выпускаются отдельно от него.

## 2. Как делался рефакторинг

1. **Аудит до правок.** По каждой подсистеме (core, services/web/api/cli, PyQt,
   Live, TUI, Liquid, сборка/CI) — карта модулей, монолиты, конкретные баги с
   механизмом и строками, дубли. Диагноз аудита проверялся по коду перед
   исправлением.
2. **Баг — сначала падающий тест.** Каждый исправленный дефект закрыт тестом,
   который краснеет на старом коде. Для Qt — offscreen-тесты с фейками; для
   Live — поддельные бэкенды и инжектируемые часы; для Liquid — отдельный
   тест-таргет с подставным worker'ом на `/bin/sh`; для TUI — PTY-тесты
   настоящего бинаря.
3. **Переносы отдельно от логики.** Монолит режется по швам ответственности,
   один модуль — один коммит, полный набор тестов после каждого. Имена, которые
   патчат тесты (`src.gui.live_mixin.LiveSession`,
   `src.core.processor.AudioConverter`, …), остаются на месте (re-export,
   шимы), а если тест должен смотреть в новое место — он переводится в том же
   коммите с тем же смыслом.
4. **Один источник истины** вместо копий: версии и пины (с тестом
   согласованности), списки опций (ASR-бэкенды, ONNX-провайдеры), нормализация
   прогресса (`core.progress.coerce_progress`), таблица провайдеров LLM,
   атомарная запись файлов, правила именования результатов.
5. **Гейты вместо дисциплины.** То, что однажды сломалось молча, получает
   проверку, которая падает громко: текстовые контракты упаковки в PR CI,
   проверка PYZ собранного бандла, `collect_required()` в спеках, проверка
   site-packages сборочного окружения, тройка torch в CI, allowlist контекста
   Docker, минимальные права токена CI.
6. **Параллельная работа по областям.** Каждая подсистема шла в своём
   git worktree с непересекающимся набором файлов; общие точки (протокол
   worker'а, `result['error']`, команды в ошибках) согласовывались явно, ветки
   сливались по одной с полным прогоном тестов после каждого слияния.

## 4. Классы ошибок, которые стоит помнить

- **Тихие пропуски в сборке.** `[skip]` при сборе пакета, пустой
  namespace-пакет вместо `gigaam`, «призрачные» dist-info из конфликтных копий
  Syncthing, editable-установка (`pip install -e`), которую modulegraph
  PyInstaller не видит («Hidden import … not found» — и сборка продолжается) —
  бандл «зелёный», а у пользователя падает импорт. Все локальные сборки Liquid
  с 2.5.3 уходили без кода PyTorch-модели. Лечится гейтом на собранном
  артефакте, а не внимательностью.
- **Пин, который отменяет диапазон.** `sympy==1.13.1` делал `torch>=2.6,<2.9`
  фактически «только 2.6» и молча откатывал torch 2.8/cu128.
- **Протокол на границе языков.** Кодировка stdout на Windows, NaN в JSON,
  ошибка без привязки к команде, реентерабельный разбор строк — всё это
  проявлялось только в паре «клиент + worker». Контракт и фикстуры, снятые с
  настоящего worker'а, держат обе стороны.
- **Остановка как самый хрупкий путь.** Live `stop()`, выход из приложения во
  время работы, отмена — исключение на любом шаге раньше оставляло состояние
  «навсегда останавливается». Теперь каждая стадия изолирована, ошибки
  собираются и показываются.
- **Тесты, пишущие в профиль пользователя.** `tests/conftest.py` изолирует
  `GIGAAM_CONFIG_DIR` на всю сессию.

## 5. Дорожная карта

По убыванию пользы; каждый пункт — отдельная небольшая ветка.

1. **Проверить на железе и в реальной сборке** то, что тестами закрыто только
   на фейках: WASAPI-loopback на Windows (в т.ч. 5.1/7.1 — ограничение каналов
   отложено), планарный ScreenCaptureKit в PyQt, выход из Liquid во время
   записи, открытие результатов из TUI на Windows, первый запуск модульных
   тестов TUI на Windows (в CI пока только компиляция).
2. **Один прогон файла для web и REST/MCP.** Web-раннер и
   `transcription_api.run_transcription` всё ещё разные последовательности
   (диагностика загрузчика, тексты ошибок, выгрузка модели) — свести к одной
   функции с параметрами вместо двух копий.
3. **`config.py`**: разделить чистые настройки (`Settings.from_env()`) и
   побочные эффекты при импорте (`bootstrap()`), читать пути лениво — уйдёт
   правка `config.ONNX_MODEL_DIR` из `app.py`.
4. **Оставшиеся крупные модули:** `utils/audio_preprocessing.py` (704),
   `utils/runtime_manager.py` (622, каталог/активация/установщик/GPU),
   `core/asr/chunking.py` (550), общий `plan_chunks` для трёх ASR-бэкендов,
   `web/static/app.js` (≈1300 строк без модулей, inline-обработчики).
5. **TUI:** типизированный `WorkerMessage`, перенос форматов/LLM/числовых
   настроек на `Setting`, оставшийся блок `handle_key`, группировка полей LLM в
   `App`.
6. **Live:** общая фабрика сессии для PyQt и worker'а (сейчас общие только
   настройки и планировщик), усиление громкости (Gain) в микшере, «живая»
   оценка спикеров (сейчас честно недоступна во всех клиентах); одновременные
   batch и Live на одной модели — решить, блокировать или сериализовать.
7. **CI:** composite-actions вместо повторяющихся шагов `build.yml`, пин и
   контрольная сумма ffmpeg, пин PyInstaller, многостадийный Dockerfile без
   компиляторов и тестовых пакетов в рантайме.
